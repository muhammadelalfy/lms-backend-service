# رفع ملفات PDF الكبيرة وتحويلها إلى JSON خفيف

الغرض: يرفع المعلم ملف PDF حتى **100 ميجابايت** (كان 25) دون أن يُحمَّل الملف في ذاكرة خادم الإنتاج (2GB). يُرفع الملف على أجزاء، ثم يستخرج منه نص خفيف بمكتبة [pdf2json](https://github.com/modesty/pdf2json)، ثم **يُحذف الملف الأصلي**، ولا يبقى إلا النص (مقاطع ومتجهات في خدمة الذكاء الاصطناعي).

## المسار

```
المتصفح  ──(أجزاء 5MB، SHA-256 لكل جزء)──►  الخادم Laravel  ──► ملف مؤقت على القرص
   │                                            │ complete
   │                                            ▼
   │                                  مهمة في طابور ai (العامل الحالي)
   │                                            ▼
   │                         خدمة الذكاء الاصطناعي ──(بث من القرص)──► pdf-extractor (Node + pdf2json)
   │                                            │  JSON خفيف: نص كل صفحة بعد تطبيع العربية
   │                                            ▼
   │                         تقطيع + تضمين (كما هو اليوم) ──► حذف الأصلي + كل الملفات المؤقتة
   ▼
شريط تقدم + إعادة محاولة لكل جزء + استئناف بعد انقطاع
```

1. **بدء الرفع** `POST /api/ai/materials/uploads` بالاسم والحجم: تُفحص الصيغة والحد والباقة قبل أي بايت.
2. **الأجزاء** `PUT /api/ai/materials/uploads/{id}/chunks/{n}`: جسم خام + ترويسة `X-Chunk-Sha256`. تُكتب الأجزاء بالتتابع في ملف مؤقت على القرص (بث، لا ذاكرة). إعادة إرسال جزء وصل سابقاً آمنة (يُقرّ ولا يُكتب مرتين). جزء خارج الترتيب يُرفض بـ409 مع `next_index`. جزء تالف أو بحجم خطأ يُرفض ولا يُكتب منه شيء.
3. **استئناف** `GET /api/ai/materials/uploads/{id}` يعيد `next_index` لمواصلة الرفع من حيث توقف.
4. **الإتمام** `POST .../complete`: فحص المحتوى (وبصمة الملف كاملاً إن أُرسلت) ثم إنشاء المادة بحالة «في قائمة المعالجة» وإرسال مهمة إلى طابور `ai`. تتحول الحالة إلى «جارٍ المعالجة» ثم «جاهزة» أو «فشلت» بالحالات الحالية.
5. **التنظيف:** الرفعات المهجورة تنتهي بعد `AI_UPLOAD_TTL_HOURS` (24 ساعة) ويحذفها أمر `ai:purge-stale-uploads` كل ساعة مع ملفاتها المؤقتة.
6. **الحماية:** مصادقة Sanctum وسياسة المعلم/المدير، ورفع يخص صاحبه فقط (غيره يرى 404)، وتحديد معدل منفصل (30 طلب بدء/إتمام في الدقيقة، 300 جزء في الدقيقة لكل مستخدم)، وحد أقصى 5 رفعات مفتوحة للمستخدم.

## ما يُحفظ وما يُحذف

| | الافتراضي (`AI_KEEP_ORIGINALS=false`) | `AI_KEEP_ORIGINALS=true` |
|---|---|---|
| PDF بعد النجاح | يُحذف الأصلي؛ `original_removed=true` | يبقى الأصلي ويُحسب حجمه |
| PDF فشل لسبب نهائي (تالف، ممسوح ضوئياً...) | يُحذف الأصلي | يُحذف أيضاً |
| PDF فشل بسبب توقف الخدمة | يبقى لتعمل «إعادة المحاولة» | يبقى |
| Word / Excel | يبقى الأصلي دائماً (مسار الاستخراج الحالي) | يبقى |

- في سجل المادة: `title` و`pages_count` و`size_original` (ما رفعه المعلم) و`size_bytes` (ما تحسبه الباقة) و`original_removed`.
- **مساحة الباقة تحسب الحجم الخفيف:** بعد الاستخراج يصبح `size_bytes` حجم النص المستخرج. وقبله يفحص الرفع الباقة بتقدير `AI_LIGHT_ESTIMATE_RATIO` (10% من حجم الـPDF افتراضياً).
- زر «تنزيل الملف» يُخفى لمادة حُذف أصلها، وتظهر عبارة توضح ذلك.
- الملف الممسوح ضوئياً (صور بلا نص) يُرفض بالرسالة: «الملف ممسوح ضوئياً ويحتاج OCR». وإن كان `OCR_ENABLED=true` في خدمة الذكاء الاصطناعي والملف أصغر من 25MB تُشغَّل الصفحات الخالية عبر Tesseract كما كان.

## الحدود (متغيرات البيئة)

| المتغير | الافتراضي | أين |
|---|---|---|
| `AI_MAX_FILE_MB` | 100 | Laravel: حد PDF |
| `AI_MAX_OFFICE_FILE_MB` | 25 | Laravel: حد Word/Excel (يُحلَّلان في ذاكرة الخدمة) |
| `AI_UPLOAD_CHUNK_MB` | 5 | حجم الجزء |
| `AI_UPLOAD_TTL_HOURS` | 24 | صلاحية الرفع غير المكتمل |
| `AI_KEEP_ORIGINALS` | false | إبقاء الأصل |
| `MAX_UPLOAD_BYTES` | 100MB | خدمة الذكاء الاصطناعي: PDF |
| `MAX_OFFICE_UPLOAD_BYTES` | 25MB | خدمة الذكاء الاصطناعي: Word/Excel |
| `EXTRACTOR_MAX_BYTES` / `EXTRACTOR_MAX_PAGES` | 150MB / 600 | pdf-extractor |
| `EXTRACTOR_WORKER_HEAP_MB` | 512 | ذاكرة خيط التحليل |
| `EXTRACTOR_TIMEOUT_MS` | 120000 | مهلة التحليل |
| `EXTRACTOR_MAX_CONCURRENT` | 1 | ملفات متزامنة (الزائد 503 ثم تعيد المهمة المحاولة) |

nginx: `client_max_body_size 25m` يبقى كما هو؛ يكفي لجزء واحد (5MB) ولأي ملف Word/Excel يُرسل دفعة واحدة، فلا حاجة لرفعه إلى 100m. أما `upload_max_filesize=20M` و`post_max_size=25M` في `docker/php.ini` فلا تتأثران لأن الأجزاء تُرسل جسماً خاماً (PUT) لا نموذجاً متعدد الأجزاء.

## حدود صريحة

- **pdf2json يحلل المستند كله في الذاكرة.** الملف يُبث إلى القرص لا إلى ذاكرة بايثون، لكن عملية Node نفسها تحتاج ذاكرة تتناسب مع الملف. القياسات (حاوية بسقف 768MB، `NODE_OPTIONS=--max-old-space-size=512`) مدونة في `lms-ai-service/pdf-extractor/README.md`. يُنصح بإبقاء الحد عند 100MB و600 صفحة؛ وما يتجاوز ذاكرة خيط التحليل يُرفض برسالة «الملف معقد جداً» (413) بدل أن يُسقط الخادم.
- الملف الذي يتجاوز حد الذاكرة يفشل بأمان (يُقتل خيط التحليل فقط) ولا تتأثر بقية الخدمة.
- الجداول لا تُستخرج كجداول Markdown في هذا المسار (pdf2json لا يعرف الجداول)؛ نصها يظهر أسطراً. المسار القديم (بدون `PDF_EXTRACTOR_URL`) يحتفظ بذلك.
- الترتيب البصري للعربية يُصلح في خدمة الذكاء الاصطناعي بعد الاستخراج، كما كان.
- pdf2json 4.x يعيد النص Unicode مباشرة (لا URI-encoding)، لذا لا يُطبَّق `decodeURIComponent`؛ تطبيقه كان سيفسد نصاً يحوي `%41` مثلاً.

## تشغيل محلي

```bash
# 1) المستخرج
cd lms-ai-service/pdf-extractor && npm ci && npm test
EXTRACTOR_TOKEN=dev npm start                 # http://127.0.0.1:8002
curl -H "Authorization: Bearer dev" -H "Content-Type: application/pdf" \
     --data-binary @test/fixtures/arabic.pdf http://127.0.0.1:8002/extract

# 2) خدمة الذكاء الاصطناعي
cd lms-ai-service && PDF_EXTRACTOR_URL=http://127.0.0.1:8002 PDF_EXTRACTOR_TOKEN=dev SERVICE_TOKEN=x uvicorn app.main:create_app --factory --port 8001

# 3) Laravel: AI_SERVICE_URL=http://127.0.0.1:8001 AI_SERVICE_TOKEN=x، ثم  php artisan queue:work --queue=ai
php artisan test Modules/Ai
```

على الخادم: `./make-ai-env.sh` يضيف `PDF_EXTRACTOR_URL/TOKEN` ويرفع `REDIS_QUEUE_RETRY_AFTER` إلى 360، و`./deploy-ai.sh <صورة الذكاء> <صورة المستخرج>` يشغّل خدمة `pdf-extractor` (profile `ai`، شبكة داخلية فقط، `mem_limit: 768m`).
